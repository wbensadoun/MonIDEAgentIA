# 1.4c — Swap gardé de la liste de messages

**État : livré éteint.** Le code des deux chemins coexiste ; seul le drapeau décide.

## Activer / désactiver

```js
localStorage.setItem('cc.flag.chatInterfaceSwap', '1'); // activer, puis recharger
localStorage.removeItem('cc.flag.chatInterfaceSwap');   // revenir au rendu historique
```

Variante build : `REACT_APP_CHAT_INTERFACE_SWAP=1`. Le drapeau est lu **une seule fois au montage**
(`useState(() => ...)` dans `AIChat/index.js`) : basculer en cours de session remonterait tout
l'historique dans un autre arbre DOM et casserait la position de scroll.

## Ce qui est swappé

Uniquement la **boucle de rendu de l'historique** (`conversationHistory.map`, ~110 lignes),
remplacée par `<MessageViewer>` alimenté par `conversationToChatMessages`.

## Ce qui n'est délibérément PAS swappé

| Surface | Pourquoi |
|---|---|
| Aperçu de streaming (`index.js:1048`) | Trois modes — fichier / workflow / texte. `MessageViewer` n'en modélise qu'un. Le brancher afficherait le flux deux fois. |
| Pills provider / modèle / mode | Hors du périmètre de la liste ; `ChatInterface` les accepte via le slot `toolbarExtra` quand le swap remontera d'un cran. |
| Panneau de modifications en attente, cartes terminal du tour courant, indicateurs de chargement | Rendus hors de la boucle, non touchés. |
| Cartes terminal archivées et images collées | Conservées, réinjectées par message via `renderMessageExtras`. |

## Parité vérifiée

Chaque comportement de l'ancienne boucle a un test qui le verrouille :

| Comportement | Test |
|---|---|
| Segments `<think>` repliés, jamais en texte visible | `chatMessages.test.js`, `MessageViewer.blocks.test.tsx` |
| Réponse assistant vide → message explicite (garde-fou ollama) | idem |
| Texte utilisateur littéral (astérisques préservées) | idem |
| Réponse assistant en Markdown | `MessageViewer.markdown.test.tsx` |
| Badge agent `nom (provider)` | `chatMessages.test.js` |
| Actions copier / relancer, désactivées pendant une génération | `MessageViewer.blocks.test.tsx` |
| Images et cartes terminal rattachées au bon message | `renderMessageExtras` (couverture par le conteneur, non unitaire) |

## Critères d'abandon

Rallumer le drapeau à `off` et rouvrir le sujet si l'un de ces points apparaît :

1. Un message de l'historique s'affiche vide, tronqué, ou avec son balisage brut.
2. Le raisonnement du modèle apparaît déplié ou mélangé à la réponse.
3. La position de scroll saute pendant une génération.
4. Une carte terminal ou une image se rattache au mauvais message.
5. Copier / relancer agit sur un autre message que celui cliqué.
6. Régression de performance visible sur un historique long (> 200 messages).

## Reste à faire avant un swap complet du panneau

- Remonter l'aperçu de streaming (trois modes) dans `MessageViewer` ou dans un composant frère.
- Câbler `ChatInterface` (et non seulement `MessageViewer`) dans `index.js`, en plaçant les pills
  dans `toolbarExtra` et le panneau des modifications en attente dans `aboveInput`.
- Vérification manuelle dans l'application Electron : aucun test automatisé ne couvre le câblage
  du conteneur lui-même.
